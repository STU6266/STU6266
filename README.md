## Currently Building

### PrintTune — Alpha / Work in Progress

A **local-first desktop advisory platform for FDM 3D printers**.

PrintTune is designed to bring printer configuration, slicer and filament data, calibration results, diagnostics, searchable knowledge and local AI guidance into one structured application.

The project is currently teaching me a lot about designing a larger application with clear boundaries between domain logic, storage, UI, validation and AI integration.

**Current stack**

`Electron` · `React` · `TypeScript` · `SQLite` · `FTS5` · `Ollama` · `Zod` · `Ajv` · `Vitest` · `Playwright`

The current Alpha is deliberately read-only for printer and firmware configuration. Local AI is provided through an abstraction around Ollama, and automatic internet research is not part of the Alpha.

[View PrintTune on GitHub](https://github.com/STU6266/PrintTune)

### unrealDice

An **offline-first React and TypeScript PWA** for tabletop dice management.

It supports reusable dice groups, saved play setups, roll history, local persistence, Quick Start templates and validated JSON backup/import workflows.

A major focus of the project was making the application useful without requiring an account or permanent backend connection.

### Speed Dungeon

A browser-based dungeon game built around short timed runs, multiple room systems and a final boss encounter.

The project combines different interaction models inside one game loop, including reaction challenges, riddles, hidden-object rooms, age-based content and mobile controls.

It gave me practical experience managing browser application state, timers, transitions and structured JSON content without relying on a frontend framework.

## How I Approach Software

I am especially interested in the parts of software development where **data, business rules, reliability and structure** matter.

When I build something, I try to understand not only how to make it work, but also:

- where responsibilities should live
- how data should be structured and validated
- how components should communicate
- how errors and edge cases should be handled
- how the project can remain understandable as it grows
- how testing can protect important behavior

I am still early in my software career, so these are areas I am actively learning rather than claiming to have mastered.
